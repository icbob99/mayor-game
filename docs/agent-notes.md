1. Сравнить новые изменения с записанной выпущенной версией. Подготовить только недостающие миграции/обновления данных; не запускать начальные seeds поверх работающей БД. `server.py:SQL_FILES` — порядок создания пустого стенда, не журнал production.
2. Применить необходимый SQL и проверить результат. Имя UI-таблицы — `game_locale_ui`; переименование отменено. Таблица `deployment`, прежний migration CLI и `--db-url` были отменены; не восстанавливать их автоматически.
3. Worker: загрузить `worker.js`, `database.js`, `auth.js`, `saves.js`, `game-storage.js` из `cloudflare/`. **Deployments -> выбрать новую версию -> Promote -> проверить Active deployment и трафик.** Latest означает загруженную версию, не активную. Существующие URL/переменные/секреты сохраняются. При необходимости — Rollback к прежней версии через Deployments.
4. Проверить API, затем публиковать frontend через release merge в `master`/GitHub Pages. Не выпускать frontend с новыми auth/save-вызовами поверх старого Worker. Источник Pages перед автоматизацией проверить в настройках; отсутствие `.github` workflow не означает отсутствие публикации GitHub Pages.
5. Проверить публичную игру и записать commit, Worker version, фактически применённые SQL. Не считать локальные тесты проверкой production.

Для первого выпуска Борис разрешил downtime и исключил обязательный backup. Это решение о данном выпуске, не универсальный отказ от резервирования будущих разрушительных изменений. В пользовательских инструкциях давать только оставшиеся действия, по одному шагу, без повторения этих условий.

## Принятый игровой дизайн

### D01. Гость, регистрация и вход

- Первый визит — гость без навязанной регистрации. «Я мэр» открывает вход, «Хочу быть мэром» — регистрацию по нику/паролю. Неизвестный ник и занятый ник имеют понятные ошибки.
- `Boris`, `boris`, ` Boris ` — один nickname_key; отображение сохраняет выбранный регистр без крайних пробелов. Email, восстановление пароля, город, аватар, постоянный титул и выбор темпа не добавлены.
- Гость хранится локально, но его игра/история/статистика не переносятся в аккаунт. Новый аккаунт начинает новую игру.
- Незарегистрированному гостю предложить регистрацию после 3-й, 8-й, 18-й завершённой игры. После отказа на последнем приглашении не докучать; не показывать приглашение при загрузке страницы.

### D02. Переключение мэр/гость

- «Хочу быть гостем» сохраняет мэра отдельно и начинает гостевую игру с нуля. Гостевые ходы не изменяют мэра и не завершают авторизацию.
- Последний режим запоминается. Возврат при действующей авторизации — без пароля, в том числе после гостевых ходов. При истечении авторизации требуется вход. Офлайн сохраняется локальный прогресс; автоматической очереди повторных PUT нет.

### D03. Другая вкладка или устройство

- Аккаунт может иметь несколько авторизаций, но только один серверный writer. Один login в B не отключает A.
- При переносе подтверждение «Продолжить игру здесь?» даётся на новом устройстве; ответ старого не требуется. Только подтверждение передаёт право записи. Старое окно не захватывает его обратно автоматически.
- Сервер проверяет writer при записи. Офлайн-вкладку невозможно мгновенно отключить; после возвращения связи она не получает право записи сама.
- ID вкладки находится в sessionStorage; Web Lock защищает от копирования при дублировании. Авторизация — `mayorAccount:tab:<id>:auth`, игра — `mayorAccount:<account>:tab:<id>:cloudSave`; общий `mayorAuth` хранит указатель и метаданные без токена.
- Закрытую вкладку можно восстановить по указателю и освободившемуся Web Lock. Чужая/старая вкладка не перезаписывает указатель активностью или expiry. Без Web Locks fallback создаёт новый ID; бесшовный reopen для него не заявлен.

### D04. Бездействие и авторизация

- Через 25 минут без действий — предупреждение, через 30 — локальное сохранение и блокировка мэра до входа. Действие игрока/«Продолжить» сбрасывает таймер; фоновые GET/PUT не считаются активностью.
- Правило действует офлайн, при сне и возврате из фона; учитывается реальное прошедшее время. Активная офлайн-игра продолжается, но серверная авторизация может истечь; после входа локальный прогресс сохраняется.
- Успешный login в одной транзакции удаляет просроченные/отозванные auth_sessions этого аккаунта, кроме строки, на которую ссылается active_game_sessions. Живые независимые авторизации остаются. Очистка запускается входом, не таймером; жёсткий лимит живых сессий не введён.

### D05. Persistence и выбор продолжения

- **Отправили и забыли:** каждое изменение сначала сохраняется локально, затем полный снимок отправляется один раз. Ход не ждёт ответа. Ответ обычного PUT, включая ошибку, не меняет игру и не запускает повтор.
- Нет очереди pending, ackTimestamp или completedGames. Timer/online/focus/reload не переотправляют обычный снимок. Следующее действие отправляет новое состояние. Потерянное завершение не повторяется при начале следующей партии; абсолютная статистика входит в новые снимки, а строка истории потерянного завершения может отсутствовать.
- Интерактивная активация/подтверждение переноса — отдельный механизм с ответом и operationId. Восстановление её потерянного ответа допустимо; фоновое восстановление активации не отправляет save.
- GUID облачного сохранения назначает сервер. Он используется при выборе/активации, не проверяется на каждом собственном PUT. Проверка writer и возрастающего writeTimestamp защищает записи после активации.
- При входе/выборе сохранять свою локальную ветку. Если исходное облако не менялось — можно продолжить локальное; если обе версии различаются — показать день/капитал/завершённость и дать выбор. Не складывать прогресс и не выбирать «лучший» автоматически. Повторно проверить увиденный GUID перед заменой.
- Собственное фоновое сохранение не должно создавать ложный конфликт. Проверяются текущий writer и равенство state/stats независимо от порядка JSON-ключей; localChanged отмечает локальную ветку, включая явный выбор local. Чистую копию можно заменить облаком без бессмысленного диалога.
- Повторный вход/явный выбор local может отправить текущий снимок один раз. Обычный reload действующего writer сохраняет локальную игру без новой активации/повторной отправки. Истечение авторизации или закрытие вкладки сами по себе не являются конфликтом.
- Состояние одного аккаунта никогда не отправлять в другой. GET/активация, пришедшие позже локального хода, не должны его затереть.

### D06. Состояние и история

- Сохраняются игровой день, показатели, кулдауны, все достижения (включая нули), признак и причина завершения. Магазин сохраняется каждый ход/после покупки.
- После повторного открытия — новая карточка; прошлые очереди последствий отменяются. Текущая карточка, порядок ответов, eventQueue и журнал решений в снимок не входят. Во время смены языка текущий порядок ответов сохраняется.

## P2. Контракт данных и API

Внешний JSON — camelCase, SQL — snake_case. Даты и writeTimestamp — UTC Unix milliseconds. Язык/звук — настройки браузера. Авторизация определяется Bearer-токеном, не входящим accountId.

`state`:
```json
{
  "gameId": "57fc1190-02a4-4cf0-bbf3-8ba1dd5c8bf9",
  "day": 1, "money": 1000000, "health": 90, "wife": 50, "threat": 15, "rating": 50,
  "cooldowns": { "police_bribe": 0, "wife_spa": 0, "assuta_vip": 0, "pr_agency": 0 },
  "achievements": { "offshore_king": 0, "untouchable": 0, "happy_wife": 0, "survivor": 0 },
  "isFinished": false, "endReason": null, "finishedAt": null
}
```
`stats`:
```json
{
  "gamesPlayed": 0, "maxMoney": 0,
  "achievements": { "offshore_king": 0, "untouchable": 0, "happy_wife": 0, "survivor": 0 }
}
```

- gameId — UUID браузера на партию. Показатели health/wife/threat/rating — целые 0–100. Cooldowns — игровые дни повторной доступности; 0 означает доступность сейчас.
- Достижения в партии — 0/1, в stats — количество завершений с достижением. maxMoney учитывает и текущую партию. Stats — абсолютные значения, не дельты.
- Причины завершения: arrest, wife_left, heart_attack, elections_lost. У незавершённой партии endReason/finishedAt — null.
- `writeTimestamp = Math.max(Date.now(), previousWriteTimestamp + 1)`; после выбора local — также больше прочитанной облачной метки. updatedAt и versionGuid назначаются сервером. `game_statuses_reject_stale_update` отклоняет UPDATE с меньшей/равной меткой; штатный SQL заранее фильтрует такие записи.

| API | Контракт |
| --- | --- |
| GET `/api/game-data` | Raw-результаты пяти таблиц контента для DAL |
| POST `/api/auth/register`, `/api/auth/login` | `{nickname,password}` -> `{account:{id,nickname},authToken,expiresAt,activeGameSessionId}`; при регистрации activeGameSessionId=null |
| GET `/api/auth/session` | `{account,expiresAt}`; проверка без продления активности |
| POST `/api/auth/activity` | `{expiresAt}`; только вследствие действия пользователя |
| DELETE `/api/auth/session` | Отозвать авторизацию; сохранения не удаляются |
| GET `/api/game/save` | null либо `{versionGuid,writeTimestamp,updatedAt,state,stats}` |
| PUT `/api/game/save` | `{gameSessionId,writeTimestamp,state,stats}` -> 204 без тела; stale/equal тоже 204, без изменений БД |
| GET `/api/game/session?gameSessionId=UUID` | `{gameSessionId}` при совпадении writer/auth, иначе 403; не продлевает активность |
| PUT `/api/game/session` | `{operationId,expectedVersionGuid,previousGameSessionId,confirmTransfer,source}` -> `{gameSessionId,save}` |

- Активация: source — local/cloud, expectedVersionGuid — увиденная версия/null; previousGameSessionId необязателен. Новый writer требует подтверждения при наличии другого владельца. Неактуальный GUID -> 409 save_conflict с save; отсутствие подтверждения -> 409 transfer_required с save.
- Повтор activation operationId сопоставляется с canonical request_hash и возвращает сохранённый ответ только пока соответствующая сессия остаётся writer. После переноса — 403, прежние права не восстанавливаются.
- Сохранение: одна транзакция/DB batch проверяет авторизацию, writer и timestamp, обновляет полный status/stats/GUID/updatedAt, при isFinished добавляет историю из того же state. PK(account_id,game_id) защищает окончание от дубля; ошибка истории откатывает статус/статистику. Старая запись не добавляет историю. Обычный save не читает/пишет квитанции.
- Ошибки API: 400 invalid_request, 401 auth_expired, 403 session_replaced, 409 save_conflict/transfer_required/nickname_taken, 503 server_unavailable. Обычный fire-and-forget PUT их не использует для UI/retry; интерактивные запросы и проверка сессии обрабатывают их по D03–D05.
